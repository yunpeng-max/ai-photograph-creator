## 2.1 入口文件：`backend/app/main.py`

```python
from fastapi import FastAPI
app = FastAPI(title="AI Photograph Creator", version="1.0.0")
```

这是整个后端的**启动入口**，做了四件事：

### ① CORS 中间件（解决跨域问题）

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.allowed_origins_list,  # 允许的前端地址
    allow_credentials=True,
    allow_methods=["*"],   # 允许所有 HTTP 方法
    allow_headers=["*"],   # 允许所有请求头
)
```

> **什么是跨域？** 前端跑在 `localhost:5173`，后端跑在 `localhost:8000`，浏览器出于安全考虑会阻止不同端口之间的请求。CORS 中间件告诉浏览器"这个后端允许前端来访问"。

### ② 注册路由

```python
app.include_router(auth.router, prefix="/api/v1")      # 认证相关
app.include_router(generate.router, prefix="/api/v1")   # 图片生成
app.include_router(points.router, prefix="/api/v1")     # 积分管理
app.include_router(options.router, prefix="/api/v1")    # 表单选项
```

> **路由是什么？** 路由决定了"哪个 URL 由哪个函数处理"。比如 `POST /api/v1/auth/login` 这个请求会被路由到 `auth.py` 里的 `login()` 函数。

### ③ 静态文件服务

```python
app.mount("/images", StaticFiles(directory=str(upload_dir)), name="images")
```

> 把 `uploads/` 目录下的图片通过 `/images/xxx.png` 这样的 URL 暴露出去，前端才能显示生成的图片。

### ④ 健康检查

```python
@app.get("/health")
async def health():
    return {"status": "ok"}
```

> Docker 等部署工具通过访问 `/health` 来判断服务是否正常运行。

## 2.2 配置管理：`backend/app/config.py`

```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env",              # 从 .env 文件读取
        env_file_encoding="utf-8",
        extra="ignore",               # 忽略 .env 中未定义的字段
    )
    database_url: str = "postgresql+asyncpg://..."  # 数据库地址
    secret_key: str = "change-me-..."               # JWT 加密密钥
    dashscope_api_key: str = ""                     # AI API 密钥
    allowed_origins: str = "http://localhost:5173"  # 允许的前端地址
    upload_dir: str = "/app/uploads"                # 图片存储目录
```

关键点：

| 配置项 | 说明 |
|--------|------|
| `database_url` | PostgreSQL 连接字符串，格式：`协议://用户:密码@主机:端口/数据库名` |
| `secret_key` | JWT 令牌的加密密钥，生产环境必须换成随机字符串 |
| `dashscope_api_key` | 阿里云 API 密钥，用于调用 AI 模型 |
| `allowed_origins` | 哪些前端地址可以访问后端（CORS 白名单） |
| `access_token_expire_minutes` | JWT 令牌有效期，默认 10080 分钟 = 7 天 |

```python
@lru_cache
def get_settings() -> Settings:
    return Settings()
```

> **`@lru_cache` 是什么？** LRU = Least Recently Used（最近最少使用）。这个装饰器让 `Settings()` 只创建一次，之后每次调用都返回同一个实例（单例模式），避免重复读取 `.env` 文件。

## 2.3 数据库连接：`backend/app/database.py`

```python
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker

engine = create_async_engine(settings.database_url, echo=False)
async_session = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)
```

### 关键概念

| 概念 | 说明 |
|------|------|
| **引擎 (Engine)** | 数据库连接池，管理所有数据库连接 |
| **异步 (Async)** | 用 `async/await` 操作数据库，等待时不阻塞其他请求 |
| **会话 (Session)** | 一次数据库操作的上下文，类似一个"事务环境" |
| **`expire_on_commit=False`** | 提交后不使对象过期，方便后续访问属性 |

### 依赖注入函数

```python
async def get_db():
    async with async_session() as session:
        yield session
```

> **`yield` 在这里的作用**：FastAPI 的依赖注入机制，请求进来时创建会话，请求处理完后自动关闭会话。类比：借用一本书（创建会话）→ 阅读（使用）→ 归还（关闭会话）。

## 2.4 认证依赖：`backend/app/dependencies.py`

```python
async def get_current_user(
    credentials: HTTPAuthorizationCredentials | None = Depends(security),
    db: AsyncSession = Depends(get_db),
) -> User:
```

这个函数是**认证网关**，任何需要登录的接口都会经过它：

```
请求进来
  ↓
① 从 HTTP 头提取 Bearer Token
  ↓
② 没有 Token? → 返回 401 "Not authenticated"
  ↓
③ 解析 JWT 令牌，提取 user_id
  ↓
④ 解析失败? → 返回 401 "Invalid or expired token"
  ↓
⑤ 从数据库查找用户
  ↓
⑥ 用户不存在? → 返回 401 "User not found"
  ↓
⑦ 返回 User 对象 → 接口函数可以直接使用
```

> **`Depends()` 是什么？** FastAPI 的依赖注入系统。`Depends(get_current_user)` 表示"这个参数的值由 `get_current_user` 函数提供"，框架自动调用它并传入返回值。

## 2.5 数据模型（ORM 模型 / 数据库表）

项目有 **3 张表**，使用 SQLAlchemy ORM 定义。

### User 表：`backend/app/models/user.py`

```python
class User(Base):
    __tablename__ = "users"

    id: Mapped[uuid.UUID]             # UUID 主键
    email: Mapped[str]                # 邮箱（唯一，建了索引）
    password_hash: Mapped[str]        # 密码哈希（不是明文！）
    nickname: Mapped[str]             # 昵称
    points_balance: Mapped[int]       # 积分余额（默认 5）
    locale: Mapped[str]               # 语言偏好（默认 "zh"）
    created_at: Mapped[datetime]      # 创建时间
    updated_at: Mapped[datetime]      # 更新时间（自动更新）
```

### Generation 表：`backend/app/models/generation.py`

```python
class Generation(Base):
    __tablename__ = "generations"

    id: Mapped[uuid.UUID]             # 主键
    user_id: Mapped[uuid.UUID]        # 外键 → users.id
    image_type: Mapped[str]           # 图片类型（如 "portrait"）
    aspect_ratio: Mapped[str]         # 宽高比（如 "16:9"）
    style: Mapped[str]                # 风格（如 "cyberpunk"）
    scene: Mapped[str]                # 场景（如 "night_city"）
    whitespace: Mapped[str]           # 留白（如 "some"）
    subject: Mapped[str]              # 用户输入的主体描述
    additional_requirements: Mapped[str | None]  # 额外要求（可选）
    assembled_prompt: Mapped[str]     # 组装好的完整英文提示词
    image_url: Mapped[str | None]     # 生成图片的本地 URL
    status: Mapped[str]               # 状态："pending"/"completed"/"failed"
    cost_points: Mapped[int]          # 消耗积分
    created_at: Mapped[datetime]      # 创建时间
```

### PointTransaction 表：`backend/app/models/point_transaction.py`

```python
class PointTransaction(Base):
    __tablename__ = "point_transactions"

    id: Mapped[uuid.UUID]             # 主键
    user_id: Mapped[uuid.UUID]        # 外键 → users.id
    change_amount: Mapped[int]        # 变动金额（正数=增加，负数=扣减）
    balance_after: Mapped[int]        # 变动后余额
    reason: Mapped[str]               # 原因（如 "registration_bonus"）
    related_generation_id: Mapped[uuid.UUID | None]  # 关联的生成记录（可选）
    created_at: Mapped[datetime]      # 创建时间
```

> **为什么用 UUID 而不是自增数字做主键？**
> 1. 全局唯一，不会暴露数据量（别人无法从 ID=100 推断你有 100 个用户）
> 2. 分布式系统友好（多个服务器可以各自生成不冲突的 ID）

## 2.6 API 路由详解

### 认证路由：`backend/app/routers/auth.py`

#### 注册：`POST /api/v1/auth/register`

```
流程：检查邮箱是否已注册 → 创建用户（初始积分=5）→ 记录"注册奖励"流水 → 返回 JWT 令牌
```

关键代码逻辑：
```python
# 1. 检查邮箱是否重复
existing = await get_user_by_email(db, body.email)
if existing:
    raise HTTPException(status_code=409, detail="Email already registered")

# 2. 创建用户（密码存的是哈希值，不是明文）
user = User(
    email=body.email,
    password_hash=hash_password(body.password),  # bcrypt 加密
    nickname=body.nickname,
    points_balance=5,  # 新用户送 5 积分
)

# 3. 记录积分流水
txn = PointTransaction(
    user_id=user.id,
    change_amount=5,
    balance_after=5,
    reason="registration_bonus",
)

# 4. 生成 JWT 令牌并返回
token = create_access_token(user.id)
```

#### 登录：`POST /api/v1/auth/login`

```
流程：查找用户 → 验证密码 → 生成 JWT 令牌 → 返回
```

```python
user = await get_user_by_email(db, body.email)
if not user or not verify_password(body.password, user.password_hash):
    raise HTTPException(status_code=401, detail="Invalid email or password")
```

> **密码验证原理**：`verify_password()` 把用户输入的密码用同样的算法加密，然后和数据库存的哈希值比较。因为 bcrypt 是单向的，即使数据库泄露，攻击者也无法反推出原始密码。

#### 获取当前用户：`GET /api/v1/auth/me`

直接返回 `get_current_user` 依赖注入得到的用户信息。

### 生成路由：`backend/app/routers/generate.py` ⭐ 核心

#### 生成图片：`POST /api/v1/generate`

这是整个项目**最核心的业务逻辑**：

```
用户提交表单
    ↓
① 检查积分是否够用（不够 → 402 Payment Required）
    ↓
② 调用 assemble_prompt() 组装专业英文提示词
    ↓
③ 创建 Generation 记录（status = "pending"）
    ↓
④ 调用 deduct_points() 扣 1 积分，记录流水
    ↓
⑤ 调用 generate_image() → 阿里云 DashScope API 生成图片
    ↓
⑥ 调用 save_image() 下载图片，保存到 uploads/ 目录
    ↓
⑦ 更新 Generation 记录（status = "completed", image_url = "..."）
    ↓
⑧ 如果第⑤⑥步出错了 → add_points() 退还积分 → status = "failed"
```

```python
# 核心代码
try:
    image_bytes = await generate_image(assembled_prompt, body.aspect_ratio)
    image_url = await save_image(image_bytes)
    generation.status = "completed"
    generation.image_url = image_url
except Exception as e:
    # 失败时退回积分
    await add_points(db, current_user, amount=1,
                     reason="generation_refund",
                     related_generation_id=generation.id)
    generation.status = "failed"
```

> **设计亮点**：生成失败时自动退还积分，用户不会白花钱。积分扣减和退款都在同一个数据库事务中。

#### 获取历史：`GET /api/v1/generations`

支持分页（`page` 和 `size` 参数），按创建时间倒序排列。返回总数、当前页、每页条数。

### 积分路由：`backend/app/routers/points.py`

- `GET /api/v1/points`：查看当前积分余额 + 积分流水列表
- `POST /api/v1/points/purchase`：购买积分（目前是占位符，返回"暂不可用"）

### 选项路由：`backend/app/routers/options.py`

- `GET /api/v1/options`：返回所有表单选项（图片类型、比例、风格、场景、留白），每个选项都包含 `key`（英文标识）、`label_zh`（中文标签）、`label_en`（英文标签）。

> **为什么把这个做成 API？** 前端不需要硬编码选项列表。如果以后要增加新的类型或风格，只需要改后端，前端自动获取最新数据。

## 2.7 核心业务逻辑 Services

### 提示词组装器：`backend/app/services/prompt_assembler.py` ⭐ 灵魂

这是项目**最巧妙的设计**。它把用户选的中文选项转换为 AI 能理解的专业英文提示词。

**设计理念**：普通用户不知道怎么写专业的 AI 画图提示词。系统让用户选择简单的中文选项，然后自动"翻译"成高质量英文提示词。

```python
# 映射表（部分示例）
IMAGE_TYPE_PROMPTS = {
    "portrait": "A professional portrait photograph of:",
    "product_photo": "Professional product photography of:",
    "cyberpunk": "Cyberpunk aesthetic, neon lights, futuristic...",
    ...
    # ...共 10 种类型、7 种比例、11 种风格、10 种场景、4 种留白
}
```

**组装结果示例**：

用户选择：
- 类型：人像 (portrait)
- 比例：16:9
- 风格：赛博朋克 (cyberpunk)
- 场景：城市夜景 (night_city)
- 留白：少量 (some)

组装后的提示词：
```
A professional portrait photograph of:
Subject: 一个穿风衣的年轻女子

Scene: Nighttime cityscape with ambient city lights
Style: Cyberpunk aesthetic, neon lights, futuristic, high-tech
Composition: Balanced composition with moderate breathing room around the subject
Aspect ratio: 16:9 widescreen landscape format
Technical requirements: High resolution, sharp focus, professional quality,
well-composed, visually striking. No text, no watermarks, no signatures.
```

> **末尾的质量后缀** `QUALITY_SUFFIX` 是固定的，告诉 AI：不要加水印、不要文字、高质量输出。

### 图片生成器：`backend/app/services/image_generator.py`

调用阿里云 DashScope 的 `qwen-image-2.0` 模型：

```python
async def generate_image(prompt: str, aspect_ratio: str = "1:1") -> bytes:
    # ① 将宽高比转为 API 需要的尺寸参数
    size = _aspect_ratio_to_size(aspect_ratio)  # "16:9" → "2688*1536"

    # ② 构造请求消息
    messages = [{"role": "user", "content": [{"text": prompt}]}]

    # ③ 在线程池中调用 API（因为 SDK 是同步的）
    response = await asyncio.to_thread(
        MultiModalConversation.call,
        api_key=settings.dashscope_api_key,
        model=settings.dashscope_model,  # "qwen-image-2.0"
        messages=messages,
        size=size,
        watermark=False,      # 不加水印
        prompt_extend=True,   # 允许 AI 扩展提示词
    )

    # ④ 从响应中提取图片 URL
    image_url = response.output.choices[0].message.content[0]["image"]

    # ⑤ 用 curl 下载图片（URL 有效期 24 小时）
    image_bytes = await asyncio.to_thread(_download_image, image_url)
    return image_bytes
```

> **`asyncio.to_thread()`**：因为 DashScope 的 SDK 是同步的（会阻塞），把它放到线程池中运行，不阻塞异步事件循环。

**下载图片为什么用 `curl` 而不是 `requests`？** 作者选择了系统命令 `curl` 来下载，支持重试机制（最多 3 次，指数退避：2 秒→4 秒→8 秒）。

### 认证服务：`backend/app/services/auth_service.py`

| 函数 | 功能 |
|------|------|
| `hash_password(password)` | 用 bcrypt 加密密码 |
| `verify_password(plain, hashed)` | 验证密码是否匹配 |
| `create_access_token(user_id)` | 生成 JWT 令牌（有效期 7 天） |
| `decode_access_token(token)` | 解析 JWT 令牌，返回 user_id |
| `get_user_by_id(db, user_id)` | 根据 ID 查用户 |
| `get_user_by_email(db, email)` | 根据邮箱查用户 |

> **JWT (JSON Web Token)** 就像一个**电子身份证**。登录后服务器发给你一个加密的令牌，后续请求带上它，服务器就能识别你是谁，不需要每次都输入密码。令牌由三部分组成（header.payload.signature），用点分隔。

### 积分服务：`backend/app/services/points_service.py`

```python
async def deduct_points(db, user, amount, reason):
    if user.points_balance < amount:
        raise ValueError("Insufficient points")  # 余额不足
    user.points_balance -= amount                 # 扣减
    # 记录流水...
    txn = PointTransaction(
        user_id=user.id,
        change_amount=-amount,    # 负数表示扣减
        balance_after=user.points_balance,
        reason=reason,
    )
```

> **积分操作的关键**：扣积分和记录流水在同一个数据库事务中，保证**原子性**——要么全成功，要么全失败，不会出现"扣了积分但没记录"的情况。

## 2.9 数据库迁移：Alembic

`backend/alembic/versions/e1ccce240f42_initial_tables.py` 是初始迁移脚本，定义了创建三张表的 SQL 操作：

```python
def upgrade():
    op.create_table('users', ...)              # 创建 users 表
    op.create_table('generations', ...)         # 创建 generations 表
    op.create_table('point_transactions', ...)  # 创建 point_transactions 表

def downgrade():
    op.drop_table('point_transactions')  # 回滚：删除表
    op.drop_table('generations')
    op.drop_table('users')
```

> **数据库迁移 (Migration) 是什么？** 就像代码的 Git 版本管理——每次修改数据库结构（加表、加字段）都记录为一个版本。`alembic upgrade head` 把数据库更新到最新版本，`alembic downgrade` 可以回滚。

# 05 - 运行流程

> 从启动项目到生成一张图片，完整追踪一次请求的**全链路**。

---

## 5.1 启动流程

### 方式一：本地开发启动 (`start.sh`)

```bash
# 1. 清理旧进程
lsof -ti:8000 | xargs kill -9    # 杀掉占用 8000 端口的进程
lsof -ti:5173 | xargs kill -9    # 杀掉占用 5173 端口的进程

# 2. 启动后端 (后台运行)
cd backend
source venv/bin/activate          # 激活 Python 虚拟环境
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000 &

# 3. 启动前端 (后台运行)
cd frontend
npm run dev &

# 4. 等待 Ctrl+C 停止
```

### 方式二：Docker 部署

```bash
cp .env.example .env              # 配置环境变量
docker-compose up -d              # 启动所有服务 (db + backend + frontend)
docker-compose exec backend alembic upgrade head  # 数据库迁移
```

Docker Compose 编排 3 个服务：
```yaml
services:
  db:       # PostgreSQL 16
  backend:  # FastAPI (端口 8000)
  frontend: # Nginx 静态文件服务 (端口 80)
```

## 5.2 用户注册流程

```
用户打开 http://localhost:5173/register
  ↓
填写昵称、邮箱、密码、确认密码
  ↓
前端：检查两次密码是否一致
  ↓ 不一致 → 显示 "密码不匹配"
  ↓ 一致 ↓
前端：POST /api/v1/auth/register
  { email, password, nickname }
  ↓
后端：检查邮箱是否已注册
  ↓ 已注册 → 409 Conflict
  ↓ 未注册 ↓
后端：hash_password(密码) → bcrypt 加密
  ↓
后端：INSERT INTO users (email, password_hash, nickname, points_balance=5)
  ↓
后端：INSERT INTO point_transactions (reason='registration_bonus', amount=5)
  ↓
后端：create_access_token(user_id) → JWT 令牌
  ↓
后端：返回 { token: "eyJ...", user: { id, email, nickname, points_balance: 5 } }
  ↓
前端：存 token 到 localStorage
前端：setUser(response.user) → 页面自动跳转到首页
```

## 5.3 用户登录流程

```
用户打开 http://localhost:5173/login
  ↓
填写邮箱、密码
  ↓
前端：POST /api/v1/auth/login
  { email, password }
  ↓
后端：SELECT * FROM users WHERE email = ?
  ↓ 用户不存在 → 401 "Invalid email or password"
  ↓ 用户存在 ↓
后端：verify_password(输入的密码, 数据库存的哈希)
  ↓ 密码错误 → 401 "Invalid email or password"
  ↓ 密码正确 ↓
后端：create_access_token(user_id) → JWT 令牌
  ↓
后端：返回 { token, user }
  ↓
前端：存 token，更新状态，跳转到首页
```

> **注意**：密码错误和用户不存在返回同样的错误信息，防止攻击者通过错误信息判断邮箱是否已注册（安全最佳实践）。

## 5.4 图片生成流程（核心链路）⭐

这是最重要的流程，涉及前后端协作和外部 API 调用：

```
═══════════════════════════════════════════════════════════
                        前端 (5173)
═══════════════════════════════════════════════════════════
用户在 HomePage 操作：
  ① 选择图片类型 → "portrait" (人像摄影)
  ② 选择宽高比   → "16:9"   (宽屏)
  ③ 选择风格     → "cyberpunk" (赛博朋克)
  ④ 选择场景     → "night_city" (城市夜景)
  ⑤ 选择留白     → "some"   (少量留白)
  ⑥ 输入主体描述 → "一个穿风衣的年轻女子"
  ⑦ 点击 [✨ 生成图片 - 消耗1积分]
  ↓
handleSubmit 被调用
  ↓
api.generate({ image_type, aspect_ratio, style, scene, whitespace, subject })
  ↓
POST /api/v1/generate
Headers: Authorization: Bearer eyJ...
Body: {
  "image_type": "portrait",
  "aspect_ratio": "16:9",
  "style": "cyberpunk",
  "scene": "night_city",
  "whitespace": "some",
  "subject": "一个穿风衣的年轻女子"
}
  ↓
═══════════════════════════════════════════════════════════
                        后端 (8000)
═══════════════════════════════════════════════════════════

Step 1: 认证检查 (dependencies.py)
  ↓ 解析 JWT → user_id
  ↓ 从数据库查用户 → User 对象

Step 2: 积分检查 (generate.py)
  ↓ user.points_balance < 1 ?
  ↓ 是 → 402 Payment Required

Step 3: 提示词组装 (prompt_assembler.py)
  ↓
  "portrait"    → "A professional portrait photograph of:"
  "16:9"        → "16:9 widescreen landscape format"
  "cyberpunk"   → "Style: Cyberpunk aesthetic, neon lights, futuristic..."
  "night_city"  → "Scene: Nighttime cityscape with ambient city lights"
  "some"        → "Composition: Balanced composition with moderate breathing room..."
  ↓
  组装结果:
  """
  A professional portrait photograph of:
  Subject: 一个穿风衣的年轻女子

  Scene: Nighttime cityscape with ambient city lights
  Style: Cyberpunk aesthetic, neon lights, futuristic, high-tech
  Composition: Balanced composition with moderate breathing room around the subject
  Aspect ratio: 16:9 widescreen landscape format
  Technical requirements: High resolution, sharp focus, professional quality,
  well-composed, visually striking. No text, no watermarks, no signatures.
  """

Step 4: 创建记录
  INSERT INTO generations (user_id, image_type, ..., status="pending")
  拿到 generation.id

Step 5: 扣积分
  UPDATE users SET points_balance = points_balance - 1 WHERE id = ?
  INSERT INTO point_transactions (reason="generation_cost", amount=-1)

Step 6: 调用 AI
  ↓
  HTTP POST → https://dashscope.aliyuncs.com/api/v1
  Body: {
    "model": "qwen-image-2.0",
    "input": {
      "messages": [{ "role": "user", "content": [{ "text": "A professional portrait..." }] }]
    },
    "parameters": {
      "size": "2688*1536",
      "watermark": false,
      "prompt_extend": true
    }
  }
  ↓
  DashScope 服务器处理...（通常需要 5-30 秒）
  ↓
  响应: {
    "output": {
      "choices": [{
        "message": {
          "content": [{ "image": "https://dashscope-result-xxx.png" }]
        }
      }]
    }
  }

Step 7: 下载图片
  ↓
  curl -o - "https://dashscope-result-xxx.png"
  ↓
  保存到: /app/uploads/a1b2c3d4-...png
  ↓
  image_url = "/images/a1b2c3d4-...png"

Step 8: 更新记录
  UPDATE generations SET status="completed", image_url="/images/a1b2c3d4-...png"

Step 9: 返回结果
  {
    "id": "a1b2c3d4-...",
    "status": "completed",
    "image_url": "/images/a1b2c3d4-...png",
    "assembled_prompt": "A professional portrait...",
    "points_balance_after": 4,
    ...
  }

── 如果 Step 6/7 出错了 ──

Catch:
  Step R1: 退还积分
    UPDATE users SET points_balance = points_balance + 1
    INSERT INTO point_transactions (reason="generation_refund", amount=+1)

  Step R2: 更新记录
    UPDATE generations SET status="failed"

  Step R3: 返回 500 Internal Server Error

═══════════════════════════════════════════════════════════
                        前端 (5173)
═══════════════════════════════════════════════════════════
收到响应
  ↓
setResult(response)           → 显示生成的图片
updateBalance(4)              → 页面顶部积分从 5 变成 4
  ↓
用户可以：
  - 点击图片放大查看
  - 展开查看组装后的提示词
  - 继续生成新图片
```

## 5.5 积分不足时的流程

```
前端：提交生成请求
  ↓
后端：检查积分 → 余额不足 → 402 Payment Required
  ↓
前端：catch 到 status=402 的错误
  ↓
setShowUpgrade(true) → 弹出升级弹窗
  ↓
弹窗显示：
  "积分不足，请升级套餐"
  Basic:  50 积分  ¥29
  Pro:   150 积分  ¥79
  Premium: 500 积分 ¥199
  [暂不可用] ← 所有按钮都是 disabled 状态
  [关闭]
```

> 这是第一版的占位 UI，付款功能还没有实际接入。

## 5.6 数据在各组件间的流动

```
localStorage ──token──→ AuthContext ──user──→ Layout（显示用户昵称和积分）
                    │                │
                    │                └──user──→ HomePage（提交生成请求）
                    │                │
                    │                └──updateBalance──→ 改变积分显示
                    │
                    └──token──→ api.ts ──Authorization header──→ 后端请求

后端 API ──数据──→ api.ts ──返回结果──→ 各页面组件（setState）
```

## 5.7 页面导航流程

```
用户访问 /
  ↓
BrowserRouter 匹配路由
  ↓ <Route element={<PrivateRoute />}>
  ↓ PrivateRoute: 检查是否登录
  ↓
  ├─ 未登录 → <Navigate to="/login" />
  │            ↓
  │          LoginPage 显示
  │            ↓ (登录成功)
  │          navigate("/") → 回到首页
  │
  ├─ 正在检查 → 显示 Loading 动画
  │
  └─ 已登录 → <Outlet />
              ↓
            <Layout />
              ├─ 侧边栏
              │   ├─ 🏠 首页    → /
              │   ├─ 🕐 历史记录 → /history
              │   ├─ 🪙 积分    → /points
              │   └─ 用户信息 + 退出按钮
              ├─ 顶栏
              │   ├─ 积分徽章
              │   └─ 语言切换
              └─ 内容区
                  └─ <Outlet /> → HomePage / HistoryPage / PointsPage
```
